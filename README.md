# KubeQuest - Kubernetes Cluster on AWS

## Overview
A fully operational Kubernetes cluster deployed on 4 AWS EC2 instances in eu-west-1 (Ireland).

## Cluster Architecture
| Node | Private IP | Role |
|------|-----------|------|
| node-1 | 10.1.35.10 | Control plane |
| node-2 | 10.1.35.52 | Worker |
| node-3 | 10.1.35.197 | Worker |
| node-4 | 10.1.35.124 | Worker |

## Deployed Components
| Component | Namespace | Purpose |
|-----------|-----------|---------|
| Flannel | kube-flannel | Pod network |
| nginx-ingress | ingress-nginx | External traffic routing |
| Kubernetes Dashboard | kubernetes-dashboard | Cluster UI |
| Prometheus + Grafana | monitoring | Metrics and visualization |
| Loki + Promtail | monitoring | Log collection |

## How to rebuild from scratch

### Prerequisites
- 4 AWS EC2 instances running Amazon Linux 2023
- SSH access via private key

### Step 1 - On all 4 nodes
Install Kubernetes components and container runtime.
See each component folder for detailed commands.

### Step 2 - On node-1 only
Initialize the control plane and install Flannel.

### Step 3 - On nodes 2, 3, 4
Join the cluster using the token generated by kubeadm init.

### Step 4 - Deploy components
Deploy all components using Helm and kubectl commands
documented in each folder.

## Verify cluster health
kubectl get nodes
kubectl get pods --all-namespaces
